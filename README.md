## 編集コンセプトと改善ロードマップ（2026-11-16）

**世界の失敗が、あなたの夜を少し軽くする。** 世界の実際の失敗や計画の誤算を、疲れた読者が夜9時に安心して読める短い日本語で伝える。事実と「AIのひと言」の創作を明確に分離し、当事者や被害者を嘲笑しない。

- **最優先：記事品質** — すべての主張を独立した出典で検証し、記事の詳細まで自然な日本語で提供する。確認できないニュースは公開しない。誤りが判明した場合は訂正・更新履歴を残す。現行の英語詳細文と既存記事の真偽は別途点検が必要。
- **編集の幅** — 重大な判断ミスをした個人・職人・従業員・選手を最優先。国・地域や題材の幅は、同程度に優れた確認済み候補の間で調整する。企業規模や分類の均等ノルマを理由に小さな珍事で埋めない。
- **AIのひと言** — 事実を捏造せず、判断や計画の意外性に温かいユーモアを添え、読者が自分の失敗を少し軽く感じられる表現を目指す。
- **今夜のひと言** — 新しい配信号の公開時、配信日と採用記事のジャンルに基づいて編集済みの日本語メッセージから自動選択し、公開JSONに保存する。読者画面と共有文面に反映する。現在は安全な定型文選択方式で、AIによる自由生成ではない。過去の公開号は既存の固定文を表示する。
- **世界地図・国別アーカイブ** — 今夜の記事の掲載国を示す地図と、国から過去記事を探せる導線を将来追加する。国名の正規化、地域バランス、スマートフォンでの操作性を検証してから公開する。

新機能の追加よりも、正確な日本語記事と信頼できる編集体制を優先する。

## 2026-11-20からの選定基準：大きな個人の大失敗

- **第一候補**：個人の重大な勘違い、誤判断、無謀な計画、取り違えなどによって、本人の予想と大きく食い違う結果が生じた実話。人物の知名度ではなく、判断の特異性と確認できる結果を重視する。
- **二段階の選定**：見出し中の人物と重大な結果は未確認候補の順位付けにのみ使用。元記事の本文と独立AI監査で「本人による失敗」と「大きな結果」がともに確認されたものだけを強く優先して先頭に配置する。
- **非採用**：小さな誤字・単純な手違いを主役に据えること、被害者の不幸を笑うこと、損害・動機・原因を創作すること。大きな個人ミスが確認できない日は本数を水増ししない。過去の公開号は変更しない。

## 世界の情報源拡張と稼働監視（2026年11月17日）

登録台帳 `data/news-source-registry.json` は、世界14市場（新聞・報道通信社・公共放送・科学・スポーツ・地域ニュース）の**追加RSS 68フィード、50媒体**を明示的に管理します。既存のBBC・NPR・各地の直接RSSも継続使用します。UPIの「Odd News」は、夜の読者向けの珍しいニュースを探すための優先収集先です。

- `news_sources.py` がRSS台帳を起動前に検証し、同じフィードの重複登録、HTTPリンク、予期しない媒体ドメインを拒否します。異なる媒体の元記事が必要なケースと、登録済み媒体の独自取材記事1本を確認できるケースを分けます。**RSSに登録されている事実だけでは記事採用されません。**
- RSSは上限付きで並行取得し、タイムアウトや配信終了・XML不正を個別に隔離します。市場単位のラウンドロビンでUS/UKの大量見出しによる他地域の圧迫を防ぎます。収集先市場はニュースの発生国を意味せず、元記事の実本文で地理を確認します。
- 定時の「Collect unverified news leads」と、直近30日の「Independently verify and publish 30-day surprises」の**双方**で使用します。検索見出しやSNS転載をそのまま配信しません。
- 2026年11月17日の実稼働では、68フィードを試行して**55件のフィードから911件の元媒体リンク候補**を取得しました。8フィードは空/不適合、5フィードは取得・解析に失敗。通常候補収集では既存媒体・検索を含め**未確認候補750件**まで収集しました。この数はニュースの検証済み記事数や配信件数ではありません。
- 停止済みのReuters旧RSS、CNN旧RSS、AP旧RSS、ABC Australia一般向けRSSなどは、台帳に「稼働中」として追加しません。稼働状況は変動するため、毎回のログの実測値を確認します。出典本文が取得できない記事は採用しません。

RSSアドレスの参考資料：[Feederの動作確認済みニュースRSS一覧](https://feeder.co/knowledge-base/rss-content/rss-lists-popular-and-useful-rss-feeds/) と報道機関の公式RSS案内（例：[The Korea Herald](https://www.koreaherald.com/rss)、[The Straits Times](https://www.straitstimes.com/RSS-Feeds)）。媒体の権利・利用規約を守り、見出しからの独立した記事執筆と出典リンクを原則とします。

## 毎日の通常配信は3本を目標、確認済み1〜3本を公開（2026年11月17日から）

## 国紹介と「30秒の小旅行」は別コンテンツ（2026-11-19）

**国紹介（地図のピン）**：国ごとの歴史・音楽・食・暮らし・言語など、
土地の魅力を伝える「COUNTRY PORTRAIT」。個別ニュースの珍事件を国全体の性格と
混同せず、記事の概要を国紹介の代用品にもしません。編集済みの本文を優先し、
まだ取材・検証できていない国については、魅力を捏造せず制作中と明示します。
国の代表写真は `TODAY_COUNTRY_PHOTOS` で個別に選定し、旅行カードの写真を
自動流用しません。

**最近の話題（国紹介内）**：`country-highlights.json` は文化・生活・芸術など、
その国を知るための出典付き時事トピックを管理します。`title`・`body` に加え、
`validFrom`・`validThrough`・`checkedOn`・`sourceName`・`sourceUrl` が必須。
公式の出典を確認してから登録し、表示日は日本時間で判定。期限切れや出典不備の
話題は画面に出しません。**時事トピックの自動執筆・情報源の自動検証は
まだ行いません。** 新しい情報の追加には編集確認が必要です。
`build_site.py` が形式、国コード、期限、`country-highlight-sources.json` に登録された**国ごとの公式情報源ドメイン**を検証します。別の国の公式資料を誤って使った場合も拒否します。

**日次監査**：`audit_country_highlights.py` と `.github/workflows/audit-country-highlights.yml` が日本時間11:17ごろに公開号の国だけを調べ、向こう7日間の時事トピックの空白を点検します。本日・翌日に確認済みのトピックがなくなった場合だけ、編集者向けGitHub Issueを重複なく1件作成します。問題がなくなれば閉じます。記事を自動生成・公開せず、ニュース配信そのものも停止しません。監査結果はGitHub Actionsの成果物に14日間保存します。GitHub Actionsの予約実行には遅延や停止の可能性があるため、絶対時刻の保証はしません。

**30秒の小旅行（記事内）**：その国の知名度が高い観光名所を紹介する独立した
「WORLD POSTCARD」。`travel-stops.json` の写真・位置情報・見どころは
文化紹介のデータとしては使いません。`FAMOUS_TOURIST_LANDMARKS` の審査済み
リスト（または編集承認された同等の観光地）から選び、同じ国の有名観光地を
用意できなければ「準備中」と表示します。ニュース現場の写真と誤認させません。

**運用上の注意**：国コードの196件は地理・表示の索引であり、196か国すべての
文化紹介や写真の編集完了を意味しません。新しい国の紹介を高品質にするには、
国別の編集本文・権利確認済み写真・期限付き時事トピックの拡充が必要です。

## 国紹介・小旅行の写真選定基準（v2）

国の紹介写真は「その国の写真である」だけでは採用しません。次の基準で編集審査します。

1. **一目で国を連想できること（最優先）**：主役はその国を象徴する建築物・自然景観・文化的ランドマーク。説明文がないと国を判別できない干潟・水面・空・道路などの接写は表紙に使わない。
2. **画面で美しく見えること**：主役が写真の中央付近で明瞭、十分な解像度、適切な露出・色・構図。スマートフォンで縦横にトリミングしても被写体が切れないこと。
3. **正確性と権利**：写真の国・場所を検証し、著作者・ライセンス・出典を記載する。無断転載や、別の国の写真への置き換えは禁止。
4. **重複防止**：同じ国・同じ名所・同じ画像が配信をまたいで過度に続かないよう履歴を確認する。ローテーションのために品質を犠牲にしない。
5. **フォールバック**：第一候補が読み込めない場合、同じ国の権利確認済みの写真を試す。写真がない場合は表示不能を明示し、無関係な写真で埋めない。

代表写真の優先順位は `index.html` の `TODAY_COUNTRY_PHOTO_RULES` で管理します。国を象徴する名所を100点、認知度の高い景観を80点程度、補足的な景色を60点未満とし、同じ国の候補間で高得点を先に表示します。点数は編集上の優先順位であり、画像の画質を自動判定するものではありません。画像そのものの目視審査も必要です。



## 画像生成APIの完全自動化（OpenAI優先・Gemini予備）

2026年11月20日以降の当日追補号、11月21日以降の通常号で、**出典審査済み4〜5記事**が揃った場合にのみ画像を生成する。各記事1枚（実写風の創作イメージ、報道写真ではない）を生成し、1200×675 WebP に変換する。全画像を検証してからのみ公開する。公開後に旧画像を削除し、iPhone の画像キャッシュを更新する。

設定手順：

1. OpenAI Platform でAPI課金を有効にし、画像生成を利用できる **OpenAI APIキー**を発行する（ChatGPT Plus/Pro の契約とは別）。
2. GitHub リポジトリの **Settings → Secrets and variables → Actions → New repository secret** に、名前 `OPENAI_API_KEY`、値にAPIキーを登録する。**キーをソースコード、PR、Issue、チャットに貼らない。**
3. GitHub Actions の `Publish approved news at night (JST)` を次の定時実行に任せるか、`Run workflow` で再試行する。**キーが設定済みならOpenAIを最優先**し、利用可能なGemini画像キーがある場合に限って予備の画像APIを使用する。

画像生成は `POST https://api.openai.com/v1/images/generations`、既定モデル `gpt-image-2.6-flare`、`medium`、16:9。ワークフローは `OPENAI_IMAGE_MODEL`、`OPENAI_IMAGE_QUALITY`、`IMAGE_PROVIDER`（`auto` / `openai` / `gemini`）で調整できる。**生成成功と全画像のファイル検証まで実際に完走した日だけ**サイトを更新し、記事に「イメージ画像（AI生成）」を明記する。API利用料金・モデルごとのクォータは画像API運営者側で管理される。画像作成は最大5記事分、既に有効な画像は再生成しない。APIが使えない場合は前の公開号を維持し、新号通知を行わない。

OpenAI の画像API仕様: https://developers.openai.com/api/reference/resources/images/methods/generate
