# Independently reviewed country material handoff

The nightly preparation and new-edition publisher consume only an explicit review file committed to trusted main at `country-material-reviews/YYYY-MM-DD-CC.json`. Never copy draft artifacts into this directory or set review flags without actual evidence. The research workflow is read-only; the early speculative worker has a four-page/four-country budget and is never awaited by article review.

Review file version 1: editionDate, countryCode, reviewer, reviewEvidence (nonempty source/visual-review references), sourceReviewed=true, editorialReviewed=true, baseDigest (SHA-256 of prior country record using country_review_apply.digest), reviewedRecord (complete canonical country record), recordDigest (same digest of reviewedRecord). Any changes to photos, travel stops, quizzes, or pending-country promotion require visualReviewed=true and licenseReviewed=true. These flags certify an independently performed review; the importer does not itself perform visual or source judgment. Preserve all existing travel-stop keys. Review each exact photo and source before committing. Reject stale baselines and wrong dates/countries. No draft artifacts confer trust.

The importer stages and validates canonical exports before applying them, defers invalid optional reviews, and is idempotent. The publisher persists the same exports alongside a newly published edition after the existing site/image QA; prepared bundles must match actual release input hashes. No change to article-selection priority or fixed nightly release time. The source/visual review itself remains an explicit editorial step. Late reviews after publication require the existing country maintenance/deployment path, not archive rewrites.

Photo-changing reviews also require `reviewedPhotoSha256` (asset path to exact reviewed JPEG SHA-256), and those bytes must already be available in the restored provenance-sensitive photo cache. Missing, altered or low-resolution bytes defer the optional update rather than introducing a new network dependency at release. Prepare and publisher use the same cache validation; differing inputs force a fresh site preflight. Topic-only updates retain existing photos.

## Automatic, source-bound notices
A separate, bounded second retrieval of the registered official page accepts only explicit cultural event types, matching event name/country/dates, scheduled status, and a visible event name. It emits no model-written claims and never promotes photographs or pending countries. The read-only main research workflow uploads `reviewed-country-topics`; prepare and publish consume only recent successful main runs of that exact workflow, verify the same edition and canonical baseline, reconstruct fixed notice text and append only to existing approved countries. A failed/missing report never blocks news. Preparation starts after research, with no additional scheduled job. The photo review path above remains independent and explicit.

## Opt-in Gemini single-pass review

The existing YORU9_ENABLE_GEMINI switch and GEMINI_API_KEY are reused; the fixed gemini-3.5-flash-lite endpoint receives three exact acquired JPEGs, current official UNESCO excerpts, Commons metadata and existing editorial drafts. Maximum one generation request per research job, no paid-model fallback, no search grounding, no retries on quota errors. Completed same-day reviews are carried forward per country even when later acquisition fails; subsequent runs can review a different country instead of repeating the first. An unchanged attempted input is skipped, and an observed quota error is carried forward to defer further same-day calls. A free-tier project is necessary for zero API charges; the workflow cannot infer billing status from a key. The model cannot choose URLs, license terms, asset paths or coordinates. Destination coordinates come from the official country-bound UNESCO inventory, not photo geolocation inference. Uncertain or incomplete reviews stay pending. The automatic artifact path is distinct from explicit manual approval; it records model evidence, never claims human review. A trusted main research artifact is only eligible for the same edition, baseline, source-bound record, exact image checksums and current publication country; the existing canonical/export, actual JPEG and mobile release gates still apply. Current dated notices remain a separately validated requirement; a country whose evergreen materials are approved can still have a topic gap.

The article research run now saves a country-scoped, checksum-bound snapshot of the official UNESCO XML rows already fetched in that run. Gemini review may use official property descriptions from those rows when a public HTML page is unavailable, but only for the exact registered site and country; no model-generated source or coordinates. The packet records source mode and property IDs. Missing or insufficient official evidence remains a defer. Per-country eligibility diagnostics contain fixed stage codes, never raw provider errors, keys or full source content.
